# 視覺管線深入設計說明（armor_vision）

> 專案首頁：**[../README.md](../README.md)**；本文件是設計細節（時序關係、投影法原理、
> Vivado LUTRAM 推斷踩坑、逐項驗證對照）的深入說明。
>
> 依《RM飛鏢FPGA視覺方案.md》第五、六節的實作順序，在官方 39 例程（OV5640 → DDR3 → RGB LCD）之上
> 插入一條純 Verilog 的視覺管線，實現：
> **① 顏色分割（紅/藍按鍵切換）② 形態學去噪 ③ 列投影找燈條 ④ 燈條配對算中心 ⑤ 畫框 + 十字**
>
> 硬體：正點原子達芬奇 XC7A35TFGG484-2 ｜ OV5640 ｜ 4.3 吋 800×480 RGB LCD
> 驗證：`xsim` 自檢測試台 20 項全部通過（紅模式 11 項 + 藍模式 9 項）

## 2. 管線架構

```
DDR3 讀出 (rddata / rdata_req / rd_vsync)
        │  RGB565 800×480 @ lcd_clk
        ▼
  輸入打一拍對齊 (data_v / x_v / de_v)
        │
        ▼
  ┌──────────────┐   mode=0 紅 / mode=1 藍
  │  color_seg   │   (R8-G8>T && R8-B8>T) 或 (B8-G8>T && B8-R8>T)
  └──────────────┘   + 亮度閘 (R8+G8+B8 >= 150)
        │  seg_mask (1bit)
        ▼
  ┌──────────────┐  ┌──────────────┐
  │ morph_nxn    │→ │ morph_nxn    │   膨脹 9×9 → 腐蝕 9×9 = 閉運算
  │ DILATE=1     │  │ DILATE=0     │   (填補燈條小洞、接起斷點)
  └──────────────┘  └──────────────┘
        │  mask_d (頂端 2*(N-1)=16 行視為 0，行緩衝尚未填滿)
        ├───────────────────────────────┐
        ▼                               ▼
  ┌──────────────┐              ┌──────────────┐
  │  video_delay │              │  proj_bond   │
  │ 延遲 8行+8像素│              │ ① 整幀 hist[x]++
  │ (原圖對齊)    │              │ ② 幀末掃描找 run
  └──────────────┘              │ ③ 取最寬兩個候選
        │ img_d                 │ ④ 下一幀用該 X 累積 Y 上下界
        │                       │ ⑤ 配對 → 邊界框/中心
        │                       └──────────────┘
        │                               │ bl/br/bt/bb/cx/cy
        │                               ▼
        │                       ┌──────────────┐
        │                       │ overlay_box  │ 畫框 + 中心十字
        │                       └──────────────┘
        ▼                               │ draw
  ┌───────────────────────────────────────────────┐
  │ 顯示合成：draw? 綠框 : (純二值? 黑白 : 原圖變暗+命中處原色) │
  └───────────────────────────────────────────────┘
        │
        ▼
  lcd_rgb_top → 4.3 吋 RGB LCD
```

### 兩個關鍵設計決定

**1. 為什麼用投影法而不是 `FindBond.v` 的連通域標記（CCL）**

燈條是「細長的垂直亮條」，這個特性讓只需要用到「每列亮像素數」這個 1D 直方圖：

- 資源：只用 800 × 10bit 的 LUTRAM（約 125 個 LUT），沒有等價類合併、label 回收、行緩衝對齊這些容易出鬼的邏輯
- 除錯：直方圖的數值可以直接看，門檻調不對一眼就看得出來

**2. 形態學窗口是「右下角對齊」，所以要補延遲**

`morph_nxn` 的窗口是 `window(x,y) = din(x-N+1..x, y-N+1..y)`，輸出的空間位置比輸入往右下偏移。
兩級串接（膨脹+腐蝕）共偏移 `N-1 = 8` 行/像素，所以：

- 二值圖在螢幕上會整體往右下偏 8 像素
- `video_delay` 把**原圖也延遲 8 行 + 8 像素** → 螢幕上原圖與二值圖完全對齊
- 框與十字用同一套像素串流座標，所以框一定貼著看到的燈條

> 這樣做的代價是 `video_delay` 需要 `8 行 × 800 × 16bit` 的 LUTRAM（約 1600 個 LUT，約佔 7A35T 的 7.7%）。
> 想省資源可以把 `MORPH_N` 改成 5（延遲變 4 行+4 像素）。

### 時間關係（重要）

| 事件 | 時機 |
|---|---|
| 像素累積到 `hist[]` | 有效顯示行（消隱期不算，`de` 由 `lcd_driver` 產生時已含垂直條件） |
| 幀末掃描 `hist` + 出框 | `rd_vsync` 脈衝後的垂直消隱期，約 802 個時鐘（消隱有約 8000 個時鐘，時間充裕） |
| 邊界框出現 | 第 2 幀末（第 1 幀清直方圖並量 X 範圍、第 2 幀量 Y 範圍、第 3 幀開始畫框），約 3 幀 ≈ 70ms |
| Y 上下界 | 用「上一幀算出的 X 範圍」累積 → **框會慢一幀**，靜態靶紙完全無影響 |

## 3. 資源使用（Vivado 2020.2，對 `armor_vision` 做 out-of-context 合成）

| 模組 | LUT | 其中 LUTRAM | FF |
|---|---|---|---|
| `video_delay`（8 行 × 800 × 16bit） | 1999 | 1664 | 128 |
| `proj_bond`（直方圖 + 掃描狀態機 + 配對） | 629 | 130 | 228 |
| `morph_nxn` ×2（膨脹 + 腐蝕） | 192 + 187 | 208 | 144 |
| `vision_cfg`（四顆按鍵消抖） | 94 | 0 | 102 |
| `color_seg` | 44 | 0 | 0 |
| 頂層與顯示合成 | 23 | 0 | 203 |
| **合計** | **3168（15.2%）** | 2002 | **805（1.9%）** |
| Block RAM / DSP | 0 / 0 | | |

7A35T 有 20,800 LUT / 41,600 FF / 1,800Kb BRAM，本管線只用掉 15% LUT、2% FF，
原 39 例程（DDR3 MIG + FIFO + 相機 + LCD）的資源仍然充裕。

> **踩過的坑（很重要）**：一開始把行緩衝寫成 `reg [WW-1:0] buf [0:NL-1][0:WIDTH-1]`，
> 讀取放在 `always @(*)`、寫入放在另一個時序區塊，Vivado **不會**把它推斷成 LUTRAM，
> 而是退化成「正反器 + 800 選 1 大 mux」——實測整個管線炸到
> **LUT 15747（75.7%）、FF 21684（52.1%）**，加進原專案一定塞不下。
> 改成 `line_buffer.v`（**同步寫 + `assign dout = mem[raddr]` 連續賦值讀** 這個標準模板）
> 之後降到 **LUT 3168（15.2%）、FF 805（1.9%）**。
> 若之後要再加行緩衝/記憶體，一律走 `line_buffer` 這個模板。

## 4. 按鍵 / LED 對應

按鍵在板上是**低電平有效**（按下 = 0），LED **低電平點亮**。

| 按鍵 | 腳位 | 功能 |
|---|---|---|
| `key[0]` | T1 | 紅 / 藍 模式切換 |
| `key[1]` | U1 | 顏色門檻 +8（上限 255） |
| `key[2]` | W2 | 顏色門檻 −8（下限 0） |
| `key[3]` | T3 | 顯示模式切換（0 = 原圖變暗+標記；1 = 純二值） |

| LED | 腳位 | 意義 |
|---|---|---|
| `led[0]` | R2 | 紅色模式 |
| `led[1]` | R3 | 藍色模式 |
| `led[2]` | V2 | 偵測到裝甲板（`bond_valid`） |
| `led[3]` | Y2 | 心跳（約 1.5Hz 閃爍，證明邏輯在跑） |

> `sys_rst_n`（U2）仍是原本的復位鍵。

## 5. 顏色判據與門檻

RGB565 先展成 8bit：

```
r8 = {R5, R5[4:2]}     g8 = {G6, G6[5:4]}     b8 = {B5, B5[4:2]}
```

| 判據 | 條件 |
|---|---|
| 紅 | `(r8-g8 > T) && (r8-b8 > T)` |
| 藍 | `(b8-g8 > T) && (b8-r8 > T)` |
| 亮度閘 | `r8+g8+b8 >= LUM_MIN_SUM`（預設 150，避免暗部紅色雜訊） |

- `T` 預設 **40**，用 `key[1]`/`key[2]` 以 ±8 調整
- 判斷式用的是**帶符號差值**，所以「白」「灰」不會被判成紅（紅判据要 R 明顯大於 G 且大於 B）

## 6. 可調參數（都在 `armor_vision.v` 的 parameter）

| 參數 | 預設 | 說明 / 調整建議 |
|---|---|---|
| `MORPH_N` | 9 | 形態學窗口大小（dart 用 9）。雜點多改 9；燈條細、怕被膨脹糊掉改 5 或 3 |
| `HIST_TH` | 48 | 一列要有幾個亮像素才算「亮欄」。燈條太短沒被偵測到 → 調小；背景大面積誤判 → 調大（範圍 0~480） |
| `MIN_W` / `MAX_W` | 6 / 240 | 燈條寬度合理範圍（像素）。太胖的色塊（例如紅牆、紅衣）會被 `MAX_W` 濾掉 |
| `MIN_GAP` / `MAX_GAP` | 10 / 520 | 兩根燈條的間距範圍 |
| `LUM_MIN_SUM` | 150 | 亮度下限，0 = 關閉 |
| `BOX_THICK` | 3 | 框線寬度 |
| `CLK_FREQ` | 25000000 | 只用於按鍵消抖時間（4.3" 800×480 的 `lcd_clk` = 25MHz） |

`armor_vision` 內部還會算 `SGUARD = MORPH_N-1`（原圖延遲量）與 `Y_GUARD = 2*(MORPH_N-1)`（忽略頂端無效行），都是自動跟著 `MORPH_N` 走的。

## 7. 模擬驗證

```
cd sim
run_vision_sim.bat            # 或者用 tools 裡的指令逐段跑
```

測試台做的事：

1. 造出與 `lcd_driver`（800×480 面板）**完全相同的時序**：`h_total=1056`、`v_total=525`、有效 800×480，
   `rddata` 比 `rdata_req` 慢一拍
2. 造出兩根紅燈條（`x=200..219` / `300..319`、`y=120..359`），左燈條中間**故意挖掉 5 行**，
   另外放一個 4×4 的紅雜點
3. 檢查 20 項：

| 檢查 | 期望 | 說明 |
|---|---|---|
| `bond_l` / `bond_r` | 208 / 327 | 燈條 x 範圍 + 形態學偏移 8 |
| `bond_t` / `bond_b` | 128 / 367 | 燈條 y 範圍 + 8 |
| `center_x` / `center_y` | 267 / 247 | 邊界框中心 |
| `bar_inside` | 0xF908 | 燈條內：命中 → 顯示原色（未變暗） |

## 8. 上板步驟

1. 用 Vivado 2020.2 開啟 `prj/ov5640_lcd.xpr`（9 個新檔案已在 `sources_1` 裡）
2. `Run Synthesis` → `Run Implementation` → `Generate Bitstream`
3. 下載 bitstream，接上 OV5640 與 4.3 吋 800×480 LCD
4. 預期看到：**畫面偏暗（原圖亮度減半）+ 兩根燈條保持原色 + 綠色框框住裝甲板 + 中心十字**，
   同時 `led[0]`（紅模式）與 `led[3]`（心跳）亮；偵測到時 `led[2]` 亮

### 對照《方案》的六個階段怎麼驗

| 階段 | 驗證方式 |
|---|---|
| 1 相機 → LCD 直通 | 把 `armor_vision` 例化註解掉即可回復原本的 39 例程 |
| 2 紅/藍顏色分割 | 按 `key[3]` 切成純二值圖 → 畫面只剩燈條是白色 |
| 3 形態學去噪 | 純二值圖下，燈條應該連續、沒有雜點（缺口被填起來） |
| 4 列投影找兩個亮區 | 框的左右邊界就是兩根燈條的 x 範圍（`bond_l`/`bond_r`） |
| 5 配對 + 算中心 | 十字交點就是裝甲板中心（`center_x`/`center_y`） |
| 6 紅/藍切換 | 按 `key[0]`，`led[0]`/`led[1]` 互換，畫面偵測跟著切換 |

## 9. 常見問題 / 除錯

| 症狀 | 可能原因與處理 |
|---|---|
| 完全沒有框，`led[2]` 不亮 | ① 顏色門檻太高/太低：按 `key[1]`/`key[2]` 邊看純二值圖（`key[3]`）邊調 ② 燈條太短：把 `HIST_TH` 調小 ③ 燈條太窄：把 `MIN_W` 調小 |
| 純二值圖裡燈條是**白色一片**（不是紅/藍色） | 相機的自動曝光把燈條打爆成白色了。燈條一旦飽和，`r8-b8` 會接近 0 就判不出來。 → 降低環境光、或把鏡頭曝光調低（改 `i2c_ov5640_rgb565_cfg.v` 裡的曝光寄存器） |
| 紅/藍判不出來、顏色偏灰白 | OV5640 的自動白平衡（AWB）會把紅色校正成白色。做顏色分割時建議關掉 AWB / AEC，改用固定曝光（改 I2C 設定） |
| 框跳來跳去 | ① 門檻剛好卡在邊緣 → 調 `HIST_TH` ② 背景有同色大面積 → 縮小 `MAX_W` 或加亮度閘 |
| 框左右對，上下偏了一點 | Y 上下界是用「上一幀的 X 範圍」量的，靶紙移動時會慢一幀；靜態無影響 |
| 畫面最上面 16 行有殘影 | 行緩衝在幀首還沒填滿，`Y_GUARD` 已把這些行排除在偵測之外；殘影只是顯示，不影響偵測 |
| 資源不夠 / 時序不過 | `MORPH_N` 改 5 或 3（LUTRAM 與延遲行都減半） |

## 10. 已知限制與下一步

- **只輸出一個邊界框**：目前取「最寬的兩個 run」當兩根燈條，畫面裡同時出現多個裝甲板時只會框住最像的一組
  → 下一步：改成多組配對，或真的去寫 CCL（`FindBond.v` 那套）
- **沒有距離/大小解算**：只給中心與邊界框，沒有把像素尺寸換算成實際距離
  → 若要報靶，需要相機內參 + 裝甲板實際尺寸（或直接用像素寬度做單調映射）
- **沒有 YOLO / 神經網路**：與 dart 倉庫一致，純經典影像處理
- **顏色分割對光照敏感**：定時或動態更新門檻（例如用整幀平均亮度做自適應 `T`）會更穩
- 可以接著做的事（依《方案》第五節）：把邊界框經 UART 送到上位機 / 加 ILA 觀察 `hist` 峰值 / 把 `bond_valid` 與中心座標接上 OLED 或數碼管
